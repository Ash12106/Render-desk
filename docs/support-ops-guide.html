01 / Roles

What the application does

AdministratorManages staff and administrator accounts, teams, branches, availability, assignments, deleted-ticket recovery, and operational data.
StaffWorks assigned tickets, updates lifecycle and activity state, posts comments, reviews customer context, and manages availability.
CustomerCreates tickets, follows status, reads the activity log, replies while tickets are open, and manages profile information.
PersistenceTickets and profiles live in MongoDB. Browser storage only keeps the current development login session.
02 / Setup

Requirements and first setup

  • Node.js 22 or newer. The Docker image uses Node.js 24.
  • npm and MongoDB 7 or newer.
  • Chrome, Edge, Safari, or Firefox.
  • Docker Desktop with Compose v2 for the container setup.
git clone <repository-url>
cd Internship-main
npm install
cp .env.example .env

Set MONGO_URI, PORT, CORS_ORIGIN, and ADMIN_PASSWORD in .env. Google variables are optional. Never commit .env. 

npm run dev

Open staff/admin at http://localhost:3000/login and customers at http://localhost:3000/customer/login.

Default administrator. Startup migrations create admin with the value of ADMIN_PASSWORD, defaulting to admin@2026. Change it before shared or production use.
03 / Containers

Docker operation

docker compose up --build -d
docker compose ps
curl http://localhost:3000/api/health/db

The app container runs the compiled Node.js/Express server and frontend. MongoDB runs as a single-node replica set because account creation, ticket creation, deletion, and restore use transactions. The one-shot initializer configures the replica set.

  • Keep data: docker compose down.
  • Reset all data: docker compose down -v.
  • Change the host port: PORT=3001 docker compose up --build -d.
  • Rebuild after changing VITE_GOOGLE_CLIENT_ID.
Healthy state. app is running, mongo is healthy, and /api/health/db returns HTTP 200 with a connected database response.
04 / Access

Using multiple devices

The server binds to 0.0.0.0, so devices on the same LAN can use the host computer's IP address: 

ipconfig getifaddr en0
http://192.168.1.25:3000/login
http://192.168.1.25:3000/customer/login
  1. Use separate administrator, staff, and customer accounts.
  2. Create staff accounts from the administrator's Manage staff screen.
  3. Customers can register from the customer login page.
  4. Test http://<host-ip>:3000/api/health/db from another device.

If access fails, check the network, host process, macOS firewall, and port availability. For a LAN demo without hot reload, use DISABLE_HMR=true npm run dev.

05 / Optional auth

Google sign-in

  1. Configure the OAuth consent screen in Google Cloud Console.
  2. Create a Web application OAuth client.
  3. Add each local or deployed origin to Authorized JavaScript origins.
  4. Set the same client ID in GOOGLE_CLIENT_ID and VITE_GOOGLE_CLIENT_ID.
  5. Restart or rebuild after changing environment values.

Customer Google sign-in creates or links a customer account. Staff Google sign-in works only for a pre-provisioned staff or administrator account with the same email.

06 / Workflows

Role-based operating workflows

Administrator. Sign in at /login; create staff accounts; edit role, team, branch, and profile details; review workload; assign tickets to available staff; inspect or restore deleted tickets.
Staff. Sign in with an administrator-created account; review assigned tickets; search and filter; create, inspect, edit, and comment; move tickets through Open -> In Progress -> Resolved -> Closed; update activity state and availability.
Customer. Register or sign in at /customer/login; raise a ticket; open it from My requests; read the shared Activity Log; reply while open; continue reading after closure.

Conversation behavior

  • Customers and staff share the same MongoDB comment records.
  • Staff comments appear in the customer activity log.
  • Customer replies appear in the staff activity feed.
  • Closed tickets are read-only; the API rejects new comments with HTTP 409.
  • Deleted tickets leave active lists and move to deleted_tickets.

08 / Data

Persistence and deleted-ticket rollback

Important collections are users, customers, tickets, deleted_tickets, comments, auditlogs, notifications, and migrations.

Deleting a ticket archives the complete document with deletedAt and deletedBy, removes it from active tickets, and retains comments and audit history. Administrators can list and restore archived tickets: 

curl -H "Authorization: Bearer <admin-user-id>" \
  http://localhost:3000/api/admin/deleted-tickets

curl -X POST -H "Authorization: Bearer <admin-user-id>" \
  http://localhost:3000/api/admin/deleted-tickets/<ticket-id>/restore

Manual smoke test

  1. Sign in as admin.
  2. Create a staff account.
  3. Register a customer in another browser.
  4. Create a customer ticket.
  5. Confirm it appears for staff.
  6. Exchange staff and customer comments.
  7. Close the ticket and confirm replies are disabled.
  8. Delete and restore it as admin.
  9. Confirm ticket and history return.
10 / Troubleshooting

Common recovery paths

White screen or stale behavior

Stop old Node processes, start one server, and hard refresh with Cmd + Shift + R. A server started before a code change will not contain newly added API routes.

Port already in use

lsof -nP -iTCP:3000 -sTCP:LISTEN
PORT=3001 npm run dev

Database unavailable

Check /api/health/db, verify MONGO_URI, review Atlas IP allowlisting, and confirm database permissions.

Authentication appears stuck

Sign out, clear site local storage, or use a private window. Each browser/device stores its own development session.

11 / Handoff

Security handoff

The current authentication model is intentionally small for development: the browser stores a user ID and sends it as a bearer token. Before public production use, add secure server-managed sessions or signed short-lived tokens, HTTPS, secret rotation, stronger password policy, audit-safe logging, and a restricted CORS origin.

Keep screenshots free of passwords, tokens, personal data, private hostnames, and real customer information.
